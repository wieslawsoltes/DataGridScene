# Compatibility matrix

## Reference and meaning of status

The behavioral reference is the public [DevExpress WPF GridControl documentation](https://docs.devexpress.com/WPF/6084/controls-and-libraries/data-grid), including [bands](https://docs.devexpress.com/WPF/15660/controls-and-libraries/data-grid/grid-view-data-layout/bands) and [edit forms](https://docs.devexpress.com/WPF/403491/controls-and-libraries/data-grid/data-editing-and-validation/modify-cell-values/edit-form). This project implements independent APIs and code. “Implemented” below means the listed DataGridScene behavior exists, not that every DevExpress option, event, visual state or edge case has parity.

There is **no complete functional, API, visual, accessibility or performance parity certification**. The browser demo is an implementation preview, not a pixel-identical reproduction or production-readiness guarantee.

## Validation is narrower than product parity

Shared contracts cover positive and rejected operations. Browser tests cover genuine interactions and exported files, not a licensed DevExpress build side-by-side. Screenshots show this implementation rather than a pixel-diff parity baseline. Hosted tests use software graphics; CPU paint time is not end-to-end frame rate, latency or hardware GPU performance. See [validation](validation.md).

## Priority follow-up areas

The largest gaps remain accessible grid providers, seamless asynchronous/server-mode data, recursive editable details, advanced editors/new-item rows and inline forms, multi-row/cell-merged layout, and data-aware printing. Each needs independent package contracts and actual browser interactions before being marked implemented. Current [row editing](row-editing.md) and [responsive form layout](row-form-layout.md) cover cached popup updates of existing rows, not insertion/deletion or remote commits.

Performance work includes live-update samples, repeatable microbenchmarks, retained native controls and operation-count browser regressions. Those measurements do not establish hardware GPU throughput, full input latency or server-mode behavior. See [performance](performance.md).
